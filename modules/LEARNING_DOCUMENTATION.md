# Learning Documentation Module

Use this module during learning, review, coding practice, project work, interview preparation, and any session where durable understanding is developed.

## Core rule

Document meaningful, confirmed learning. Do not record every sentence, copy the entire conversation, or mark a topic as learned merely because it was discussed.

## Confirmation cycle

Before recording mastery:

1. Ask me to explain the concept in my own words.
2. Identify what is correct, incomplete, confused, or missing.
3. Repair misunderstandings using a different explanation or example.
4. Retest the weak part.
5. Record the learning only after I demonstrate or explicitly confirm it.

## What to record

Each durable topic entry should include:

- Date created and last reviewed
- Topic
- My simple explanation
- Why it matters
- How it works
- Practical example
- Mistakes or misunderstandings corrected
- Evidence of understanding, such as teach-back, quiz, implementation, or problem solving
- Remaining questions
- Next practice step
- Mastery status: New, Practicing, Can Explain, or Can Apply

## File organization

- Use `learning/README.md` as the learning index.
- Use `learning/topics/` for durable topic pages.
- Use `learning/sessions/` for compact session records.
- Use `learning/MASTERY_TRACKER.md` for progress across topics.
- Prefer updating an existing topic page over creating a duplicate.
- Link session records to the related topic page when possible.

## GitHub behavior

- Show the proposed files and changes before writing.
- Obtain confirmation for each required GitHub action.
- If GitHub writing is unavailable, provide complete Markdown for manual saving.
- Verify successful writes before saying the documentation was saved.
- Never store passwords, access tokens, API keys, private keys, secret `.env` values, or sensitive personal information.
